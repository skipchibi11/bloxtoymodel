# BloxToy Model

テキスト（例：「ネズミ」）から、BloxToy形式のブロックモデル（JSON）を生成するAIモデルを **0から学習** して作るプロジェクト。

## 目的

- 「ネズミを作って」のような指示から、ブロックで組み立てたモデルを生成する
- 最初は既存素材に近いものの生成から始め、素材の増加に合わせて段階的に学習し、将来的にはあらゆる形に対応する

## 前提条件

| 項目 | 内容 |
|---|---|
| 既存素材 | BloxToy JSON 約150件（今後も増える予定） |
| 学習環境 | Mac本体のみ（PyTorch の MPS＝Apple GPU を使用） |
| 費用 | 無料（すべてローカルで動作、外部APIは使わない） |
| 商用利用 | 可能な構成にする |

## 決定事項

### 1. モデル構成

```
「ネズミ」→【テキスト理解部】→ 数値ベクトル →【ブロック生成部】→ BloxToy JSON
              （学習済みを借用・固定）            （0から自作・学習）
```

- **ブロック生成部**：0から自作する小型 Transformer（1000〜3000万パラメータ程度）
  - ブロックを「位置・色など」のトークン列にして、1個ずつ順番に生成する（自己回帰方式）
- **テキスト理解部**：学習済みのテキストエンコーダを、学習させずにそのまま使う

### 2. テキストエンコーダ

**採用：`sentence-transformers/paraphrase-multilingual-mpnet-base-v2`**（2026-11-14 に変更）

- ライセンス：Apache 2.0（商用利用可・無料）
- 日本語と英語の両方に対応。ラベルのベクトル化に使うだけなので、Mac の CPU で十分動く
- 意味が近い言葉は近いベクトルになる（「ネズミ」≈「ハムスター」≈「mouse」）ため、学習データにない単語にもある程度対応できる
- 素材が増えても単語リストを作り直す必要がない
- `src/config.py` で版（revision）を固定している。版が変わるとベクトルが変わり、追加学習が成り立たなくなるため

**変更の理由**：7件の素材と未知の単語8個（ネズミ・ハムスター・チューリップ・イルカ・松の木・箱・ぶた・蜂）で、どの素材に一番近いと判定するかを比べた。

| モデル | 正しく選べた数 | 類似度の幅 | ライセンス |
|---|---|---|---|
| intfloat/multilingual-e5-small（当初の候補） | 4/8 | 0.81〜0.90（ほぼ差がない） | MIT |
| paraphrase-multilingual-MiniLM-L12-v2 | 7/8 | 0.18〜0.97 | Apache 2.0 |
| **paraphrase-multilingual-mpnet-base-v2** | **8/8** | 0.29〜0.97 | Apache 2.0 |

予備候補：paraphrase-multilingual-MiniLM-L12-v2（軽量）、cl-nagoya/ruri シリーズ（日本語特化、Apache 2.0）

使わないもの：OpenAI 公式 CLIP（モデルカードで研究用途が想定されており、商用製品には推奨されていないため）

> ⚠️ ダウンロード時に Hugging Face のモデルページで、その時点のライセンスを必ず再確認すること。
> MIT / Apache 2.0 では、著作権表示とライセンス文を同梱する義務がある（LICENSE ファイルやクレジット欄に記載）。

### 3. BloxToy JSON の形式

```json
{
  "app": "3dworld", "type": "blocks", "title": "Bee",
  "data": {
    "version": 1, "grid": 16,
    "blocks": [ { "x": 9, "y": 8, "z": 7, "c": "#ffffff", "s": "cube", "m": "glass" } ]
  }
}
```

| キー | 内容 | モデルでの扱い |
|---|---|---|
| `grid` | 基本は16（16×16×16のマス目）。24 の素材もある（book.json） | 16×16×16 として扱う。範囲外のブロックは除外して警告 |
| `x`,`y`,`z` | 位置（0〜15）。yが高さで、地面はy=0 | まとめて位置トークン1つ（4096種類） |
| `c` | 色。カラーピッカーで自由に選ぶ（#RRGGBB） | RGB各チャンネルを16段階に丸め、まとめて色トークン1つ（4096種類） |
| `s` | 形。`cube` のみ | 学習しない（出力時に `cube` を付ける） |
| `m` | 素材（任意）。`glass`・湯気・炭酸などいろいろあり、今後も増える | カテゴリのトークン。なし＝`none`。一覧は学習時に自動で集める（下記） |
| `title` | 作品名 | 英語ラベルとして使う |

- **素材の一覧は学習時に自動で作る**
  - 前処理のときに `data/` の全ファイルを読み、見つかった素材を `materials.json` に記録する
  - 番号は**追加のみ**（一度振った番号は変えない）。番号が変わると、追加学習で前回の学習結果が使えなくなるため
  - モデルには素材の枠を多めに確保しておく（例：64枠）。新しい素材が増えても、モデルを作り直さずに追加学習できる
  - 新しい素材は、それを使った作品を学習させるまで、モデルは使い方を知らない
- ブロック数はおよそ54〜470個。1ブロック3トークンなので、1作品は最大約1400トークン
- 長い系列は Mac の GPU で極端に遅くなるため、学習時は「件数×長さ」が一定（6000トークン）を超えないよう自動で小分けにして処理する（`--token-budget`）

### 4. データ戦略

150件は0から学習させるには少ないため、以下で補う。

- **正規化**：色を16段階に丸め、範囲外・重複位置のブロックを除く
- **データの水増し**（学習時にランダムに適用。ファイルは増やさない）
  - 縦軸まわりの回転（4通り）× 左右反転（2通り）＝ 8通り
  - 水平方向（x, z）に最大2マスずらす。高さ（y）はずらさない
  - 色は変えない（「赤いバラ」が青くなるとラベルと合わなくなるため）
- **ラベル付け**：自動で付けるラベル（`title` とファイル名。`cat_01.json` → `cat`）に加え、`labels.json` に日本語名や言い換えを追記できる
- **（必要に応じて）外部データ**：Objaverse などの公開3Dデータをボクセル化して BloxToy 形式に変換する（各データのライセンスを確認したうえで使う）

### 5. 段階的な学習

- 素材が増えたら、前回の学習結果（チェックポイント）から**追加で学習**する。最初からやり直す必要はない
- 最初は小さく始める（少数カテゴリ・小さいグリッド）

### 6. 評価

- ブラウザで生成結果を3D表示するビューアを作る
- 浮いているブロックの割合などを自動でチェックする

## 見通し

| 素材数 | 期待できること |
|---|---|
| 〜数百件 | 学習データに近いものの生成が中心 |
| 数千〜数万件 | カテゴリ単位で新しいものを生成できる |
| 10万件〜 | 「何でも作れる」レベルを目指せる |

## マイルストーン

素材が次の件数に達したら、前処理 → 学習 → テストを行い、結果をこの表に記録する。

| # | 素材数 | 状態 | 素材の集め方 | テストすること | 合格の目安 |
|---|---|---|---|---|---|
| M0 | 7件 | ✅ 完了 | — | 仕組みが一通り動くか | 学習から生成までが動く |
| M1 | **30件** | 未着手 | 種類を広く（動物・花・食べ物・乗り物・建物・物など） | 評価の仕組みを作り、基準となる点数を取る | 学習済みのものを再現できる。学習していない言葉で、意味の近い素材を選べる |
| M2 | **150件** | 未着手 | **1種類5件以上を10種類以上**含める | コピーではない新しい形を作れるか | 学習に使っていない素材と似た形を作れる。丸写しばかりにならない |
| M3 | **500件** | 未着手 | カテゴリごとにまとまった数をそろえる | カテゴリ単位の生成。色の指定（「ピンクの○○」） | 新しい形の割合が増える。色の指定が効く |
| M4 | **1000件** | 未着手 | 種類の幅をさらに広げる | M3のテストの安定性。モデルを大きくする必要があるか | 学習していない種類でも、それらしい形になる |
| M5 | **3000件** | 未着手 | — | 学習していないものへの対応力 | 学習は一晩（数時間）で終わる |

※ 合格の目安の数値は、M1で基準となる点数を取ってから決める。

### 各マイルストーンでの作業

- **M1（30件）までに**
  - 評価の仕組みを作る：素材の約1割を検証用として学習に使わずに取っておき、下の指標を自動で計算するスクリプト
  - 未学習語のテストセットを作る（例：イルカ→クジラ、チューリップ→花、ハムスター→動物）
- **M2（150件）までに**
  - 色違いの水増し（色を塗り替えて「ピンクのクジラ」のようなラベルを自動で付ける）
  - ひらがな対策（日本語特化のテキストエンコーダ ruri と比較テスト）
- **M3（500件）までに**
  - ラベルのベクトルを保存して使い回す（前処理を追加分だけにする）
  - 生成の高速化（KVキャッシュ）
- **M5（3000件）の前に**
  - 学習が一晩で終わらなくなったら、クラウドのGPU（Kaggle・Colab など）を検討する

### 評価の指標

| 指標 | 測り方 | わかること |
|---|---|---|
| 再現度 | 学習済み素材のラベルで生成し、元の素材と形の一致度（重なり具合）を測る | 覚えたものを作れるか |
| 汎化度 | 検証用に取っておいた素材のラベルで生成し、その素材との一致度を測る | 学習していないものを作れるか（一番大事な指標） |
| 新規性 | 生成物と、一番近い学習素材との一致度を測る（95%以上なら丸写し） | コピーではなく新しい形を作っているか |
| 意味の正しさ | 未学習語のテストセットで、期待した種類を選べた割合 | 言葉の意味を正しく扱えているか |
| 破綻率 | 途中で止まった生成・宙に浮いたブロックの割合 | 形として成立しているか |

### 結果の記録

| # | 実施日 | 素材数 | 学習ステップ | 結果メモ |
|---|---|---|---|---|
| M0 | 2026-11-14 | 7件 | 3000 | 学習済み（ハチ・クジラ）は97〜100%一致で再現。イルカ→クジラ（意味の近い素材から形を借りる）。ネズミ・mouse→プレゼント箱（近い見本がない）。ピンク色のくじら→バラ（色の指定は未対応）。ひらがなの単語の区別が弱い（くじら≈ひまわり） |

## 使い方

```bash
# 初回のみ：環境を作る
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# 前処理（素材を追加したら毎回実行）
.venv/bin/python -m src.preprocess

# 前処理のテスト
.venv/bin/python -m tests.test_preprocess

# 水増しの見た目を確認（outputs/ に書き出す → ビューアで表示）
.venv/bin/python -m src.preview_augment bee.json

# 3Dビューア → http://localhost:8000/viewer/
#   画面左上の入力欄に「ネズミ」などと入れて「生成」を押すと、その場で生成して表示する
#   （python3 viewer/serve.py で起動した場合は表示のみ。生成はできない）
.venv/bin/python viewer/serve.py
```

```bash
# 学習（新規）。1ステップ約0.6秒（M4）
.venv/bin/python -m src.train --steps 3000

# 素材を増やしたら：前処理 → 前回の続きから追加学習
.venv/bin/python -m src.preprocess
.venv/bin/python -m src.train --steps 2000 --resume

# 生成（outputs/ に保存 → ビューアで表示）
.venv/bin/python -m src.generate ネズミ -n 3
#   --temp 0.7      ランダムさ（初期値0.7。1.0にすると途中で崩れることがある）
#   --guidance 3    指示に従う強さ（1 = 強調なし）
```

### トークンの形式

- 1ブロック ＝ 3トークン：`位置 色 素材`
  - 位置 = y×256 + z×16 + x（4096種類）、色 = r×256 + g×16 + b（4096種類）
- ブロックは下から上へ（y → z → x の順）＝ 位置番号の小さい順に並べる。積み木を下から組む順番
- 語彙 = 特殊3 ＋ 位置4096 ＋ 色4096 ＋ 素材64 ＝ 8259
- 1作品＝最大約700トークン（現在の素材で最大713）
- 当初は1ブロック7トークン（y, z, x, r, g, b, 素材）だったが、系列が長すぎて Mac の GPU では1ステップ約30秒かかった。3トークンにまとめて約0.6秒に短縮した

### モデル（ブロック生成部）

- 小型 Transformer：8層・幅384・約1850万パラメータ（`src/model.py`）
- テキストのベクトルを4つの「条件トークン」に変換して系列の先頭に置く
- 位置トークンには x・y・z、色トークンには r・g・b の埋め込みを足す（隣のマスや似た色が近いことを最初から持たせる）
- 学習中は10%の確率で条件を「なし」にする → 生成時に「条件あり」と「なし」の差を強調して、指示に沿わせる（classifier-free guidance）
- 生成時はルール（文法マスク）で、必ず正しい BloxToy JSON になるようにする（位置は下から上の順・重複なし・登録済みの素材のみ）
- チェックポイントにはテキストエンコーダの版・素材の一覧を記録し、追加学習のときに食い違いがあれば止める

## フォルダ構成

```
bloxtoymodel/
├── README.md
├── requirements.txt
├── LICENSE          # コードのライセンス（MIT）
├── data/            # BloxToy JSON 素材（手を加えない）。data/LICENSE = CC0
├── labels.json      # 追加ラベル（日本語名など）
├── materials.json   # 素材の一覧（自動生成・追加のみ。手で番号を変えない）
├── processed/       # 前処理の結果（dataset.pt）
├── outputs/         # 生成結果・プレビュー（ビューアに表示される）
├── src/
│   ├── config.py        # 設定値
│   ├── vocab.py         # JSON ⇔ ブロック配列 ⇔ トークン列
│   ├── augment.py       # 水増し
│   ├── preprocess.py    # 前処理
│   ├── preview_augment.py
│   ├── model.py         # ブロック生成部（Transformer）
│   ├── train.py         # 学習・追加学習
│   └── generate.py      # 生成
├── tests/           # 動作確認
├── checkpoints/     # 学習済みの重み（last.pt）と学習ログ
└── viewer/          # 3Dビューア
```
